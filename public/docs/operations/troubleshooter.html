Port Troubleshooter

Focused read-only port diagnosis using one serialized SSH session.

v2.0.0Source-backed

Evidence collected

  • Administrative and physical link state.
  • Configured and detected media.
  • Error counters, CRC/FCS, drops/discards and collisions where reported.
  • PoE state and draw.
  • Learned MAC addresses.
  • UNP identity/profile evidence.
  • LLDP neighbor evidence.
  • Existing Live Port Inventory fallback fields.

Conservative interpretation

Unknown AOS output remains Not reported. The workflow does not infer unsupported values. Findings may surface enabled-without-carrier, interface errors, PoE faults, zero PoE draw, multiple learned MACs or a live link with no endpoint evidence.

Safety

Port Troubleshooter is read-only and does not change configuration.

UI request binding

The browser binds a diagnosis to the exact device, port and modal session that launched it so an older response cannot overwrite a newer Port Details view.

Source-backed detail

Evidence collection and interpretation

A diagnosis is scoped to one physical port and uses one serialized SSH session. It collects only the evidence needed for that port: interface state and media, counters, PoE, forwarding entries, UNP identity, LLDP neighbors and recent Portivo-observed activity. Existing Live Port Inventory data is used only as a fallback when a targeted query omits a field.

Parsers are conservative. Unknown output remains Not reported; unsupported commands reduce coverage instead of becoming faults. Findings can highlight carrier mismatch, CRC/FCS errors, drops, collisions, PoE faults, zero draw, multiple MAC addresses or a live link without endpoint evidence. The workflow is read-only.

UI isolation

Each request is bound to the exact device, port and open details session. A late response from a previous port cannot overwrite the evidence for the port currently displayed.
