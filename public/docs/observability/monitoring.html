Monitoring modes and credentials

Full monitoring, Management only and read-only credential profiles.

v2.0.0Source-backed

Monitoring modes

Full monitoring runs configured background health workers. Management only pauses selected background monitoring while keeping on-demand inventory, operations, audits, automation, troubleshooting and administration available.

Granular services

  • Switch availability.
  • Stack Member Health.
  • Power / UPS.
  • Incident detection.

Monitoring Credentials

Profiles can use read-only SSH or SNMPv3. They are stored separately from personal SSH sessions and Automation credentials.

SNMPv3

Portivo uses SNMPv3 authPriv. New profiles prefer SHA-256. SHA and DES remain explicitly labeled legacy compatibility modes. Verification uses sysDescr on a switch or UPS and does not send configuration commands.

Source-backed detail

Freshness, confirmation and honest state

Switch availability is a lightweight credential-free TCP probe of the configured SSH port. A first failure receives a shorter retry path; persistently offline devices can be polled less frequently. Current state, consecutive failures and timestamps feed the incident detector, but polling and incident generation remain separate controls.

When background monitoring is paused, Dashboard and Power must not present cached values as live. The interface marks monitoring as paused while retaining last-known evidence and scan time. On-demand workflows still collect fresh evidence through their own authenticated sessions.

Capacity controls

Health concurrency, normal and offline intervals, long-offline thresholds and connection timeouts are bounded configuration values. Increase concurrency only when Portivo and the management network can absorb the additional parallel probes.
